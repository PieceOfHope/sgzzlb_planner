# 코드 구조 분석 (Code Structure — 이식 관점)

이 문서는 이 디렉토리에 복사해 둔 `resource-planner.html`(원본 `newslg-resource-planner`와 동일, 3,483줄)을 줄 단위로 훑으며, **각 부분을 그대로 재사용할지 / 값만 바꿀지 / 통째로 새로 짤지**를 표시합니다. "왜 이렇게 만들었는지"의 배경은 [PORTING_GUIDE.md](./PORTING_GUIDE.md)를 참고하세요.

> 라인 번호는 지금 이 디렉토리의 `resource-planner.html`(2026-08-20 복사본) 기준입니다. 코드를 고치기 시작하면 곧바로 밀립니다.

**재사용 등급 범례**

- 🟢 **그대로 재사용** — 게임에 무관한 범용 로직/패턴. 이름만 다듬으면 됨.
- 🟡 **구조는 재사용, 값/필드는 교체** — 함수 시그니처와 알고리즘은 유지하되, 게임 데이터(자원 종류, 효과 키, 비율 등)에 맞춰 상수/필드를 다시 채워야 함.
- 🔴 **게임 종속 — 전면 재작성** — 삼국지 전략판의 실제 시스템을 확인하기 전엔 손댈 수 없는 부분.

## 8. 이식 착수 시 체크리스트 (요약)

1. §2의 `GD`/`RES`/`BOX_SIZES` 등 전역 상수를 삼국지 전략판 데이터로 교체하기 전에는 나머지가 전부 동작하지 않습니다 — **여기가 최우선 착수 지점**입니다.
2. §3의 유틸리티 함수는 손대지 말고 그대로 두세요 (함수 시그니처가 안정적이라 위 레이어 재작성 중 재사용 가능).
3. 둔전/자원 상자/영지 스왑(§4, §5 중 🔴 표시)은 삼국지 전략판에 대응 시스템이 없다면 **통째로 삭제**하는 게, 억지로 끼워맞추는 것보다 낫습니다.
4. 탭4의 입력 표(§6)를 참고해서 새 입력 UI를 만들 때는 `restoreCaretToEnd()`와 `syncRoster()`의 "활성 input 스킵" 두 가지 패턴을 반드시 처음부터 적용하세요 — 둘 다 오늘 실제로 겪은 버그에서 나온 교훈입니다.
